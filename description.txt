Create a golang terminal app that converts .org files to .odt with custom conversion parameters. The main requirements are that tabs are maintained exactly as given; line breaks turn into paragraphs, and text wrapped in underscores _ and asterisks * become underline/italics and bold; and certain org markers are ignored in the output. 

The app MUST NEVER assume extra spaces etc., and should maintain all other aspects of the text exactly as written. 

Here are the app details:

I. This is a terminal app written in go using bubbletea. On startup, it should as the following questions:

    1. What file should be converted? Confirm that the file exists.

    2. Conversion options:
        
        a. Should underscores be converted to italics or underlines? (Default to italics.)
        
        b. What character pattern indicates that all following format markers (eg. _ and *) should be ignored for that line. (Default three backticks ```)
        
        c. What character indicates that any formatting in the next word (before a space) should be ignroed. (Default single backtick `)

        d. Should tab characters remain tabs, or turned into ➥ characters? (Default remain tabs.)

        e. What section marker indicates a scene change? Only asterisks are allowed. (Default '**')

        f. Output path + filename. (Default same folder, same filename, new extension.)

II. Convert the file by following these rules:

    1. Find the line that starts with either #+begin_story or #+story_start and start converting from this point. Any text before should be ignored.

    2. Every line in the org file should be a paragraph.

    3. Text between underscores is made italics or underline depending on the option selected.

    4. Text between asterisks is bold.

    5. Text between both should be both italics and bold.

    6. If the option is set, convert tab characters into ➥. Otherwise, keep all tab characters, including multiple consecutive tabs! DO NOT remove any tabs.

    7. If any format markers are left open at the end of the line, close them. Formatting should never stay across paragraphs.

    8. Once you reach the line starting with #+end_story or #+story_end, stop convertion.

    9. Add a final paragraph that just contains "END", centered.

    10. Any line that starts with a hash # should be ignored. It is a comment.

    11. Any line that begins with the scene change characters (eg. **) should be considered a scene change. Add a new paragraph with a centered '*'.

III. Save the file using the given filename.
